# 更新交付闭环（2026-10-28）

## 冻结目标

- 发布前用 App 内置公钥验证 appcast 和 DMG，不以长度相同代替签名匹配。
- 发布可从标签、Release、feed 提交后的中断恢复；远端不可读取时停止，不把网络错误当成不存在。不覆盖既有不同标签或安装包。
- 新默认：运行时每 6 小时检查、后台下载签名更新、退出后安装；长时间不退出时 24 小时后提醒。保留 Sparkle 已存储的用户选择，不在启动时强制写偏好。
- 设置说明中英一致，明确下载不等于安装，不承诺 App 退出时仍能接收推送。
- 独立目录中的定向反例、全量回归通过后才集成。公开发布还须核验线上签名 feed、远端包和实际旧版升级到新版本。

## 不做

不改密钥/授权/用户数据，不轮换签名身份，不覆盖 0.3.5 标签，不修改网络配置，不自动退出用户正在使用的 App；不扩入官网重设计或推送服务。

## 门禁与收口

- blocker 仅限数据安全、秘密泄漏、错误发布、更新/启动不可用、无界重试或上述显式目标不满足。
- 测试首先用合成数据证明签名篡改与同大小错包被拒绝，再证明发布中断可以恢复。
- 线上连接当前失败：保留原 main 的未提交 appcast；不宣称已经发布，不把本地合成测试当成真实生产升级。
- 收口：定向测试 → 冻结候选 → 一次全量测试 → 集成核对 → 公开发布门禁 → 旧版实际升级验收。缺少外部服务时记录明确待办，不换源、不重复上传。
